# Execution checkpoint

Use this checkpoint immediately before an action and again before accepting its
result. It points to canonical rules; it does not replace them.

Before acting:

- confirm the recorded Scrum stage, active role, one outcome, file scope, and
  authority boundary;
- confirm every triggered state, stall, threat, UI/UX, and full-writing module is
  loaded;
- for a mutation, record the recoverable baseline, one hypothesis, expected
  discriminating result, progress evidence, attempt budget, and stop condition;
- confirm the selected test route can expose the material claim and that required
  capability, not nominal model tier alone, controls assignment.

Before accepting:

- inspect the actual diff and exact tool output; do not accept a self-reported
  summary as evidence;
- run the applicable Definition of Done with an independent verifier when the
  runtime permits;
- confirm no secret, personal data, private source, source extract, or local
  private path entered the artifact or commit;
- update the task attempt record, decisions, impediments, DoD evidence, and Scrum
  state that changed.

If a stop condition fired, do not mutate again. Preserve the evidence and apply
`core/stall-recovery.md`.
